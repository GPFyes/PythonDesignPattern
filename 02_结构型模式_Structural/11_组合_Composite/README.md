# 组合模式 (Composite Pattern)

## 定义
将对象组合成树形结构以表示"部分-整体"的层次结构，使得用户对单个对象和组合对象的使用具有一致性。

## 原理
统一叶子节点和容器节点的接口，使得客户端不需要区分两者，可以统一处理。

## 角色
- **Component**: 抽象组件，定义统一的接口
- **Leaf**: 叶子节点，表示具体的文件
- **Composite**: 容器节点，表示文件夹，可以包含子组件

## 优点
1. 统一处理：客户端可以一致地处理单个对象和组合对象
2. 树形结构清晰：容易构建复杂的树形结构
3. 扩展性强：新增组件类型不影响现有代码

## 缺点
1. 难以限制类型：可能无法限制组合中的组件类型
2. 设计复杂：需要维护组件层次结构

## 适用场景
- 树形结构：如文件系统、组织结构
- 部分-整体场景：需要表示"部分-整体"层次结构
- 统一接口：希望客户端忽略单个对象和组合对象的区别
