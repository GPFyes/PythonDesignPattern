# 装饰器模式 (Decorator Pattern)

## 定义
动态地给一个对象添加额外职责，比继承更灵活。

## 原理
装饰器模式通过包装对象来动态添加功能，在不改变原有类的情况下扩展其行为。

## 角色
- **组件(Component)**: 定义对象接口，可以给这些对象动态地添加职责
- **具体组件(ConcreteComponent)**: 实现组件接口的原始对象
- **装饰器(Decorator)**: 维持组件引用，并实现与组件接口一致的外包接口
- **具体装饰器(ConcreteDecorator)**: 负责给组件添加额外职责

## 优点
- 灵活添加职责：比继承更灵活地扩展对象功能
- 避免继承膨胀：避免因功能扩展导致的类数量爆炸
- 可以在运行时动态添加或撤销职责

## 缺点
- 多层装饰复杂：多层装饰可能使代码变得复杂难懂
- 调试困难：错误可能隐藏在多层装饰中

## 适用场景
- 需要动态添加功能，且功能可以动态撤销
- 需要通过继承来扩展类不切实际或不可能
- 处理那些独立性很强的功能
