# 观察者模式 (Observer Pattern)

## 定义

定义对象间的一对多依赖关系，当一个对象（Subject/主题）的状态发生改变时，所有依赖它的观察者（Observer）都会收到通知并自动更新。

## 原理

采用**发布-订阅（Publish-Subscribe）机制**。主题（Subject）保存观察者的引用，主题状态变化时遍历所有观察者并调用其更新方法。

## 角色

- **Subject（主题/被观察者）**：维护观察者列表，提供注册、注销观察者的接口，状态变化时通知所有观察者
- **Observer（观察者）**：定义更新接口，收到通知后执行相应操作
- **ConcreteObserver（具体观察者）**：实现Observer接口，维护与主题的一致性

## 优点

- **解耦**：主题与观察者之间是抽象耦合，主题不需要知道观察者的具体实现
- **动态关系**：可以在运行时动态添加或移除观察者
- **触发机制**：状态变化自动触发通知

## 缺点

- **内存泄漏**：如果观察者没有被正确注销，主题会一直持有观察者引用，导致内存泄漏
- **通知顺序**：通知顺序依赖实现，可能导致意外行为
- **过度通知**：频繁的状态变化可能导致大量通知，影响性能

## 适用场景

- **事件系统**：GUI事件处理、消息推送
- **MVC架构**：Model变化时更新View
- **数据绑定**：数据模型变化时自动更新UI
- **分布式系统**：消息队列、事件总线
