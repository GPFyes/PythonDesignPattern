# 迭代器模式 (Iterator Pattern)

## 定义

顺序访问集合元素，不暴露集合的内部表示（底层的物理存储结构）。

## 原理

将遍历集合的责任从集合本身转移到迭代器对象。迭代器封装了遍历集合的逻辑，提供统一的访问接口，使得客户端可以透明地遍历不同类型的集合。

## 角色

- **Iterator（迭代器）**：定义访问和遍历元素的接口
- **ConcreteIterator（具体迭代器）**：实现迭代器接口，记录当前位置，提供遍历方法
- **Collection（集合/容器）**：定义创建迭代器的接口
- **ConcreteCollection（具体集合）**：实现集合接口，返回具体迭代器

## 优点

- **统一遍历接口**：为不同集合提供统一的遍历方式
- **隐藏内部结构**：客户端不需要知道集合的内部实现细节
- **职责分离**：集合负责存储，迭代器负责遍历，符合单一职责原则
- **可扩展性**：可以轻松添加新的集合和迭代器

## 缺点

- **增加复杂度**：需要额外创建迭代器对象
- **性能开销**：对于简单集合，直接遍历可能更高效

## 适用场景

- **统一遍历不同集合**：需要遍历数组、列表、树等不同数据结构
- **隐藏集合实现**：不想暴露集合的内部结构给客户端
- **多次遍历**：需要在同一集合上同时进行多次遍历
