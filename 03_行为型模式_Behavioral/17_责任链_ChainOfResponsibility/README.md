# 责任链模式 (Chain of Responsibility)

## 定义
将请求沿链传递，直到有对象处理它。每个处理者决定是否处理或传递给下一个处理者。

## 原理
责任链模式是一种行为型设计模式，允许将请求沿着处理者链逐个传递，直到有一个处理者处理该请求。每个处理者都包含对下一个处理者的引用，当收到请求时，处理者可以选择处理请求或者将请求传递给链中的下一个处理者。

## 角色
- **Handler（处理者抽象类）**: 定义处理请求的接口，并持有下一个处理者的引用
- **ConcreteHandler（具体处理者）**: 实现了处理请求的具体逻辑，决定是否处理或传递请求

## 优点
1. **解耦**: 发送者和接收者之间没有直接的耦合关系
2. **灵活处理**: 可以动态地改变链中的处理顺序或添加/删除处理者
3. **单一职责**: 每个处理者只需关注自己应该处理的请求

## 缺点
1. **可能难以调试**: 请求沿着链传递，调试时可能难以追踪
2. **性能开销**: 如果链过长，每次请求都需要遍历整个链
3. **不易观察**: 难以确定请求最终是否被处理

## 适用场景
- 多个对象可以处理同一个请求，具体哪个对象处理运行时刻决定
- 需要在不明确指定接收者的情况下，向多个对象中的一个提交请求
- 日志系统：不同级别的日志由不同的处理器处理
- 权限验证：多级权限检查
- 事件处理系统
