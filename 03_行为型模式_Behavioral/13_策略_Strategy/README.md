# 策略模式 (Strategy Pattern)

## 定义
定义一系列算法，将每个算法封装起来，使它们可以相互替换。策略模式使得算法可以独立于使用它的客户端而变化。

## 原理
把算法封装到策略类中，客户端通过上下文对象选择具体的策略来执行。

## 角色
- **Strategy**: 抽象策略类，定义所有算法的公共接口
- **ConcreteStrategy**: 具体策略类，实现具体的算法
- **Context**: 上下文类，持有一个策略类的引用，根据需要切换算法

## 优点
1. 算法可自由切换
2. 避免使用多重条件判断（if-else）
3. 符合开闭原则
4. 算法的细节封装在策略类中，客户端无需关心

## 缺点
1. 类的数量会增加
2. 客户端需要理解所有策略类的区别

## 适用场景
1. 多种算法需要动态切换
2. 避免使用复杂的条件分支
3. 需要在运行时选择不同的算法
