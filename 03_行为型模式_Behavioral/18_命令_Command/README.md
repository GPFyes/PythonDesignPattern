# 命令模式 (Command Pattern)

## 定义
将请求封装为对象，从而允许用户通过不同的请求来参数化其他对象，支持撤销和恢复操作。

## 原理
命令对象封装了请求本身，包括执行操作所需的所有信息。通过将请求的发送者与接收者解耦，命令模式允许灵活地配置和扩展系统。

## 角色
- **Command（抽象命令）**: 定义执行操作的接口
- **ConcreteCommand（具体命令）**: 实现具体操作，绑定到接收者
- **Invoker（调用者）**: 发起请求，触发命令执行
- **Receiver（接收者）**: 知道如何执行操作

## 优点
- 解耦：请求发送者和接收者无需相互了解
- 支持撤销/重做：可以保存命令历史实现撤销操作
- 容易扩展：新增命令不影响现有代码

## 缺点
- 类数量增加：每个操作都需要创建具体命令类

## 适用场景
- 需要撤销/重做功能的场景
- 日志记录和事务管理
- 队列请求和延迟执行
